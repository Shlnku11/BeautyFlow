# DESIGN_SYSTEM.md — BeautyFlow Design System

## 0. Актуальное направление (2026-10-06)

Текущий интерфейс использует сдержанную систему рабочего пространства. Этот раздел и §11 заменяют исторические clay/glass рекомендации ниже: они сохранены как запись прежнего направления, но не являются правилами для новых экранов.

- Фон `#FAFAFA`, поверхности `#FFFFFF`, границы `#E5E7EB`, основной текст `#111827`, вторичный `#6B7280`, акцент `#7C3AED`.
- В тёмной системной теме: фон `#0A0A0B`, поверхность `#141416`, границы `#26262A`, основной текст `#F4F4F5`, вторичный `#A1A1AA`, акцент `#8B5CF6`. Тема выбирается через `prefers-color-scheme`, переключателя нет.
- Рабочие таблицы, календарь и панели используют плотные сплошные поверхности; карточки — радиус 8–12px и тонкую тень. Glass и clay в текущем UI не применяются.
- Ссылки не подчёркиваются; анимация ограничена короткими изменениями цвета/opacity и появлением секций. `prefers-reduced-motion` отключает движение.
- Рабочая плотность: body 14px, контролы 36px, h1 24px, h2 18px, h3 15px. Денежные и временные значения используют `tabular-nums`.
- Для интерактивных иконок разрешён Lucide React; если иконка не нужна для смысла, используйте текст. Отдельная icon-библиотека в этом блоке не добавлялась.

Стиль: профессиональный CRM-интерфейс, фиолетовая палитра, **умеренный** soft glassmorphism. Принцип: **данные важнее декора**. Стекло — для рамки приложения, sticky header лендинга и акцентных поверхностей; таблицы, календарь и графики — на плотных поверхностях.

Коэффициенты контраста в этом документе **вычислены по формуле WCAG 2.x** для указанных пар цветов. Пары, не отмеченные числом, обязаны быть проверены скриптом контраста на Этапе 12 (TESTING_STRATEGY §12) до использования.

## 3. Типографика

- Шрифт: **Inter** (Google Fonts через `next/font`, подмножества **`latin` и `cyrillic`** — текущий `layout.tsx` подключает только `latin`, это обязательно исправить на Этапе 3).
- Font stack: `"Inter", system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans", sans-serif`.
- Цифры в таблицах/деньгах/времени: `font-variant-numeric: tabular-nums`.
- Шкала (размер/межстрочный/вес): `display` 32/40/700 · `h1` 24/32/700 · `h2` 20/28/600 · `h3` 16/24/600 · `body` 14/22/400 (CRM-плотность) · `body-lg` 16/24/400 (публичная запись, формы на мобильных) · `small` 12/18/500 (метки, бейджи; минимум 12px) · `mono` — не используется.
- Базовый размер на мобильных для полей ввода — **16px** (предотвращает автозум iOS).
- Длина строки текстовых блоков ≤ 72 символов; выравнивание по левому краю, без `justify`.

## 4. Spacing, радиусы, тени

- Сетка 4px (`--space-*`). Отступы карточек: 16 (mobile) / 24 (desktop). Плотность таблиц: строка 48px (desktop), 56px (touch).
- Радиусы: поля/кнопки `md` (12), карточки `lg` (16), модальные/hero-карточки `xl` (24), бейджи/аватары `full`.
- Тени: `sm` — поля/кнопки; `md` — карточки в hover; `lg` — выпадающие меню, модалки; `glass` — только стеклянные поверхности. Не более одной тени уровня `lg` на экране.

## 5. Стеклянные поверхности (glass)

**Где допустимо (whitelist):**
1. Фон приложения: декоративные размытые фиолетовые пятна (`primary-300/400`, opacity ≤ 0.35) на `surface-app`.
2. Sidebar и верхняя панель (topbar).
3. KPI-карточки dashboard (**фон карточки**; цифры и подписи остаются контрастными).
4. Hero-карточка публичной записи, карточки входа/регистрации.
5. Оверлей (backdrop) модальных окон — размытие фона за модалкой.

**Где запрещено (blacklist):** таблицы и строки таблиц, календарная сетка и события, поля форм и их контейнеры, выпадающие списки/меню, графики (область построения), toast, текст на изображениях. Эти элементы — плотные поверхности; содержимое modal/drawer может быть clay-карточкой согласно §10.

**Параметры:**
| Параметр | Значение |
|---|---|
| Фон | `--surface-glass` (`rgba(255,255,255,0.72)`) или `--surface-glass-strong` (0.86) для sidebar |
| `backdrop-filter` | `blur(16px) saturate(140%)` desktop; `blur(10px)` ≤768px |
| Граница | 1px `--border-glass` |
| Тень | `--shadow-glass` |
| Минимальная непрозрачность для поверхности с текстом | **0.72** (ниже — запрещено) |
| Вложенность | максимум **один** слой стекла в одной точке (стекло в стекле запрещено) |
| Fallback | `@supports not (backdrop-filter: blur(1px))` и `@media (prefers-reduced-transparency: reduce)` → сплошной `rgba(255,255,255,0.96)` без blur |
| Контраст | текст на стеклянной поверхности проверяется на **худшем** фоне под ней (на пятне `primary-300`): основной текст `neutral-900` обязан давать ≥ 7:1, вторичный `neutral-600` ≥ 4.5:1 |
| Производительность | не более 4 стеклянных элементов в viewport одновременно; не анимировать `backdrop-filter` |

## 6. Компоненты

Общие состояния: **hover** (фон +1 ступень), **focus-visible** (кольцо 2px `--focus-ring`, offset 2px, контраст ≥ 3:1 с соседними цветами; `outline: none` без замены запрещён), **active/pressed** (−1 ступень/`primary-800`), **disabled** (`neutral-100` фон, `neutral-600` текст, `cursor: not-allowed`, `aria-disabled`; не заменяет текстом причину — причину показывать рядом), **loading** (спиннер + `aria-busy`, ширина кнопки не меняется, повторный клик блокируется), **error** (граница `danger-solid`, иконка, текст ошибки под полем, `aria-invalid` + `aria-describedby`).

- **Кнопки:** `primary` (фон `primary-600`, текст белый, hover `700`), `secondary` (белый фон, граница `neutral-400`, текст `neutral-900`), `ghost` (прозрачная, текст `primary-700`), `danger` (фон `danger-solid`, белый), `link`. Размеры: `sm` 32px, `md` 40px, `lg` 48px; touch-target ≥ 44×44px на мобильных. Иконка-кнопка обязана иметь `aria-label`.
- **Inputs/Textarea:** высота 40px (44px mobile), фон белый, граница `--border-control`, радиус `md`, label **всегда видимый** над полем (placeholder не заменяет label), подсказка и ошибка под полем. Поля с маской (телефон, деньги) — `inputMode` и `autocomplete` по типу.
- **Selects:** нативный `<select>` на мобильных; на desktop — Headless UI Listbox/Combobox с клавиатурой (стрелки, Enter, Esc, type-ahead). Список — плотная поверхность, тень `lg`.
- **Checkbox/Radio/Switch:** размер ≥ 20px (область нажатия 44px), граница `--border-control`, выбранное — `primary-600`; Switch имеет текстовую подпись.
- **Таблицы:** плотная поверхность, шапка `neutral-50` + `text-secondary` 12px uppercase не используется (читаемость кириллицы) — шапка 12–14px weight 600; зебра `neutral-25`; hover строки `primary-50`; числа выровнены вправо, `tabular-nums`; сортировка с `aria-sort`; на мобильных (<768px) таблица превращается в **список карточек** (ключевые 3–4 поля), горизонтальный скролл — только для оправданных широких таблиц с видимой подсказкой.
- **Карточки:** плотная (`surface-solid`, `shadow-sm`, радиус `lg`); стеклянные — только KPI/hero по §5.
- **Бейджи:** высота 24px, радиус `full`, текст 12px/600 + (опц.) иконка; цвета — §1.4.
- **Модальные окна:** фон страницы — стеклянный backdrop `rgba(31,17,66,0.45)` + blur; панель — непрозрачная clay-карточка с радиусом `xl`; максимум ширины 560px (форма) / 720px (детали); на мобильных — bottom sheet на всю ширину; фокус-ловушка, возврат фокуса на триггер, закрытие Esc/кнопкой, `role="dialog"` + `aria-modal` + `aria-labelledby`; деструктивные подтверждения — отдельный диалог (`role="alertdialog"`).
- **События календаря:** см. §1.5; минимальная высота события 24px; в текст — время, клиент (усечение с `title`), услуга; статус — иконка + стиль (pending: пунктирная граница; cancelled: зачёркнуто и приглушено; no_show: иконка). Блокировки — штриховка `neutral-200/100` + подпись «Недоступно». Рабочие часы — белый фон, нерабочие — `neutral-50`. Линия «сейчас» — `danger-solid` 2px.
- **Графики:** Recharts; цвета серий — `primary-600`, `primary-400`, `info-solid`, `success-solid`, `warning-solid` (максимум 5 серий); подписи осей `neutral-600` 12px; сетка `neutral-200`; всегда подпись значений в tooltip + таблица-альтернатива (`<details>`/кнопка «Показать таблицей») для скринридеров; один цвет — не единственный различитель (маркеры/штрихи у линий).
- **Sidebar (desktop ≥1024px):** ширина 264px (свёрнутая 72px), стеклянная `surface-glass-strong`; пункты 44px высотой, активный — фон `primary-100` + текст `primary-800` + левая полоса 3px `primary-600` + `aria-current="page"`. Группы пунктов по роли (см. UI_UX_SPEC §3).
- **Mobile navigation (<768px):** нижняя панель из 4–5 пунктов (по роли) + «Ещё» (drawer с остальным), высота 64px + `env(safe-area-inset-bottom)`; активный пункт — иконка + подпись (подпись обязательна). Планшет 768–1023px: свёрнутый sidebar 72px с tooltip.
- **Toast:** плотная поверхность, `role="status"` (success/info) и `role="alert"` (error); 5 с (error — до закрытия); не перекрывает нижнюю навигацию.
- **Skeleton:** `neutral-100` → `neutral-50` shimmer 1.4с; при `prefers-reduced-motion` — статично.

## 7. Анимации

Только `opacity`/`transform`; `--duration-fast/base`; при `prefers-reduced-motion: reduce` все переходы ≤ 1ms (кроме смены состояния фокуса). Запрещено: параллакс, постоянные анимации, анимированное стекло.

## 8. Тёмная тема — решение

**В MVP тёмной темы нет** (`color-scheme: light`). Причины: стекло и контрастные пары рассчитаны/проверены для светлой темы; двойная проверка контраста увеличит объём. Архитектура готова: все цвета — CSS-переменные; позже добавляется набор значений под `:root[data-theme="dark"]` + проверка тех же пар. До тех пор запрещено использовать `dark:`-классы Tailwind.

## 9. Доступность (обязательные критерии)

1. Контраст: текст ≥ 4.5:1 (крупный ≥ 3:1), границы контролов и фокус ≥ 3:1 (проверено для токенов §1; остальные — скриптом).
2. Все интерактивные элементы доступны с клавиатуры, порядок фокуса = визуальный порядок, нет «ловушек» кроме модалок.
3. Видимый фокус везде (`:focus-visible`), skip-link «Перейти к содержимому» первым в DOM.
4. Формы: label связан с полем, ошибки — текстом + `aria-describedby`, при отправке с ошибками фокус на первое невалидное поле + сводка ошибок `role="alert"`.
5. Масштабирование: не отключать зум (убрать `maximumScale: 1` из текущего `layout.tsx`); интерфейс корректен при 200% и ширине 320px.
6. `prefers-reduced-motion`, `prefers-reduced-transparency`, `prefers-contrast: more` (усиливает границы и отключает стекло).
7. Язык документа `lang="ru"`; даты/деньги форматируются `Intl` (ru-RU) в поясе бизнеса.
8. Таблицы — семантические (`th scope`), календарь — как сетка с доступной альтернативой «Список записей дня».
9. Целевые области касания ≥ 44×44px на мобильных.
10. Проверка: автоматическая (axe) на каждом ключевом экране + ручной проход клавиатурой и скринридером перед релизом (Этап 13).

## 10. Claymorphism

Clay добавляет мягкий рельеф плотным поверхностям. Он не заменяет glass и не снижает читаемость рабочих данных.

### Токены

| Назначение | Токен | Значение |
|---|---|---|
| Базовый clay-фон | `--surface-clay` | `#f2eff9` |
| Выпуклая поверхность | `--surface-clay-raised` | `#f8f6fc` |
| Вдавленная поверхность | `--surface-clay-inset` | `#eeebf5` |
| Выпуклая тень | `--shadow-clay-raised` | светлая и фиолетовая внешние тени |
| Вдавленная тень | `--shadow-clay-pressed` | парные внутренние тени |
| Карточки | `--radius-clay-card` | `24px` |
| Контролы | `--radius-clay-control` | `16px` |

Tailwind-утилиты: `bg-clay`, `bg-clay-raised`, `bg-clay-inset`, `shadow-clay`, `shadow-clayPressed`, `rounded-clay-card`, `rounded-clay-control`.

### Правила применения

- **Clay:** кнопки, карточки, KPI, формы и списки-карточки в CRM; поля ввода используют вдавленную поверхность. Hover поднимает карточку, active нажимает кнопку.
- **Glass:** sticky header лендинга, рамка приложения, sidebar, hero и выделенные KPI. Стеклянная поверхность остаётся в whitelist скрипта контраста.
- **Плотные поверхности:** таблицы, календарная сетка и события, меню, содержимое dialog и графики сохраняют непрозрачный фон и не получают clay-тени.
- **Публичная запись:** hero использует glass, этапы формы — clay; сами элементы формы остаются хорошо различимыми и доступными.
- **Адаптивность:** тени мягкие и малые на узких экранах; рабочая сетка календаря остаётся плоской.
- **Предпочтения пользователя:** `prefers-reduced-transparency` переключает стекло на solid, а `prefers-reduced-motion` отключает движение и transitions.
- **Контраст:** текст neutral-600 и neutral-900 проверяется на каждом clay-фоне скриптом `check:contrast`; для основного текста требуется ≥ 4.5:1.

## 11. Neutral workspace rules (актуальные)

§10 описывает прошлую визуальную версию. Текущие реализации используют нейтральные поверхности и системные light/dark токены из `packages/client/src/styles/tokens.css`.

- Sidebar: 240px, сворачивание до 56px; topbar 56px; контент до 1440px с полями 24px на desktop.
- На ширине менее 768px sidebar скрыт, появляется нижняя навигация; календарь принудительно остаётся в режиме дня.
- Календарь: ручная CSS Grid сетка, 56px колонка времени, 15-минутные строки высотой 20px, рабочий диапазон 08:00–21:00. Неделя показывает семь дней; месяц — сетку 7×5, максимум три записи и счётчик остальных.
- Запись в сетке — сплошной нейтральный блок с тонкой акцентной границей слева. Клик открывает диалог; свободный слот открывает создание с заполненными датой, временем и мастером.
- Кнопки и поля используют радиус 8px и высоту 36px; фокус всегда виден. Диалог имеет сплошной backdrop без blur, закрывается Escape и кнопкой.
- Landing hero показывает скриншот работающего dashboard (`packages/client/public/images/dashboard-preview.png`), а не CSS-мокап. Тексты интерфейса остаются в `src/shared/i18n/ru.ts`.
- `prefers-color-scheme: dark`, `prefers-reduced-motion` и `prefers-reduced-transparency` учитываются токенами и fallback-стилями.
