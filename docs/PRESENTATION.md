# Защита проекта BeautyFlow

## Текст выступления

1. **BeautyFlow.** Система управления записью и ежедневной работой салона. Код разделён на клиент, API и общий пакет контрактов.
2. **Проблема.** Разрозненные таблицы и мессенджеры приводят к конфликтам расписания, потере истории клиента и ручным напоминаниям.
3. **Решение.** Онлайн-запись, календарь команды, клиенты, оплаты, уведомления и аналитика в одном приложении.
4. **Функции.** Клиент выбирает услугу и время; команда управляет расписанием и визитами; владелец видит показатели и платежный журнал.
5. **Технологии.** Vite, React 19, Express 5, MongoDB 8, Node 24 и TypeScript monorepo.
6. **Дизайн.** Inter Variable, светлая/тёмная нейтральная палитра, токены и адаптивные компоненты.
7. **Booking engine.** Слоты учитывают услугу, длительность, расписание, буферы, исключения и часовой пояс; DST проверяется отдельно.
8. **Защита от двойной записи.** occupiedKeys резервируют занятые ячейки, уникальный multikey index блокирует конкурирующие дубликаты.
9. **Изоляция.** Tenant context, Mongoose plugin и проверки связанных сущностей удерживают чтение и запись в рамках businessId.
10. **Payments.** Денежные суммы хранятся целыми числами; append-only journal, idempotency key и транзакции поддерживают charge/refund.
11. **Уведомления.** MongoDB queue, dedupe, lease и worker с backoff повторяют временно неудачную доставку.
12. **Структура и тесты.** Route → Service → Repository → Model; на 2026-10-07 115 unit/integration/API тестов и два race-теста зелёные.
13. **Демо.** Показать лендинг, недельный календарь, карточку записи, платежный журнал. Для авторизованного локального сценария сначала запустить существующую MongoDB на 27018.
14. **Ограничения.** Не проверены production DNS/TLS/SMTP/backup restore/monitoring; Tailwind 3 dev chain имеет 5 high advisories. Следом — staging, inbox уведомлений, SMS/push и acquiring.

## Вопросы и ответы

### Как система не допускает двойные записи?

Запись резервирует все занятые интервалы в occupiedKeys. Уникальный multikey index защищает от совпадения при параллельных запросах.

### Как разделены данные разных салонов?

API context определяет businessId; Mongoose tenant plugin ограничивает запросы; сервис проверяет связи между сущностями. A/B тесты подтверждают отказ в доступе к чужим данным.

### Почему суммы целые?

Хранение в minor units не использует float арифметику. Обновление оплаты и append-only transaction выполняются вместе в Mongo транзакции.

### Что произойдёт при сбое email?

Уведомление остаётся в MongoDB очереди, а worker повторяет доставку по backoff до maxAttempts. Dedupe key не допускает дубликатов.

### Что нужно для production?

Настроить Mongo replica set, домен/TLS/SMTP и секреты; пройти staging E2E/security, проверить backup restore и мониторинг.
