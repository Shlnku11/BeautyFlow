# DASHBOARD_SPEC.md — Dashboard владельца

Dashboard использует **только реальные данные БД**. Статических demo-цифр в рабочих виджетах нет (в пустой базе — пустые состояния). Эндпоинты: **MVP** — `DSH-01` (4 KPI), `DSH-05` (ближайшие записи) для owner/admin и `MST-01` для master (без денег); **post-MVP** — `DSH-02` (график выручки), `DSH-03` (загрузка мастеров), `DSH-04` (топ услуг) (API_CONTRACTS §14). Разделы ниже, относящиеся к post-MVP эндпоинтам, сохранены как проектная спецификация. <!-- CHANGED: A2b -->

## 1. Период и фильтры

- Параметры: `preset=today|week|month|last_month` (по умолчанию `month`) **или** `from`/`to` (локальные даты бизнеса, включительно, максимум 366 дней); `staffId` (опционально); `compare=true` добавляет предыдущий период той же длины (`previous`). *MVP-UI использует только период; `staffId` и `compare` поддерживаются контрактом `DSH-01`, но в интерфейсе не показываются.* <!-- CHANGED: A2b -->
- Границы: период `[from 00:00, to+1д 00:00)` **в часовом поясе бизнеса**, переведённые в UTC (DST-безопасно: границы считаются от локальной даты, а не прибавлением 24 ч).
- `week` = ISO-неделя (пн–вс) текущей локальной даты; `month` = календарный месяц; `last_month` — предыдущий.
- Все запросы начинаются с `$match: { businessId }` (из сессии); `staffId` из query проверяется на принадлежность бизнесу (иначе `404`).
- Доступ: owner и admin (`dashboard:read`). master → `403` (использует `MST-01`).

## 2. Метрики и формулы

| Метрика | Формула | Источник / поле времени |
|---|---|---|
| Выручка нетто | Σ`amountMinor` по `type=charge` − Σ`amountMinor` по `type=refund` | `transactions.occurredAt ∈ период` |
| Выручка брутто | Σ`charge` | то же |
| Возвраты | Σ`refund` | то же |
| Записей всего | count(appointments) | `appointments.startAt ∈ период` |
| По статусам | count по `pending/confirmed/completed/cancelled/no_show` | то же |
| Доля отмен | `cancelled / total` (0 при `total=0`) | то же |
| Доля no_show | `no_show / total` | то же |
| Новые клиенты | count(customers, `isDeleted:false`) | `customers.createdAt ∈ период` |
| Загрузка мастера | `bookedMinutes / availableMinutes × 100`, ограничено 100 | §3.5 |
| Топ услуг | по `serviceId` среди записей `completed`+`confirmed`+`pending` (кроме `cancelled`,`no_show`); сортировка `count` или `netRevenueMinor` | `appointments` ⟕ `transactions` |
| Ближайшие записи | `status ∈ {pending,confirmed}`, `startAt ≥ now`, по возрастанию, лимит | `appointments` |

Примечания: выручка привязана к **дате движения денег**, а не к дате визита (оплата вперёд/после). Фильтр `staffId` для выручки использует `transactions.staffId` (копия с записи при создании платежа). Валюта — валюта бизнеса (мультивалютность вне MVP).

## 3. Агрегации MongoDB (псевдо-пайплайны)

### 3.1 Выручка
```
transactions.aggregate([
  { $match: { businessId, occurredAt: { $gte: fromUtc, $lt: toUtc }, ...(staffId && { staffId }) } },
  { $group: { _id: "$type", sum: { $sum: "$amountMinor" } } }
])   // net = sum(charge) − sum(refund)
```
Индекс: `{businessId, occurredAt}` (+`{businessId, staffId, occurredAt}`).

### 3.2 Ряд выручки по дням — post-MVP (`DSH-02`) <!-- CHANGED: A2b -->
`$group` по `$dateTrunc: { date: "$occurredAt", unit: "day", timezone: business.timezone }`, сумма со знаком (`charge:+`, `refund:−`), затем заполнение пропущенных дней нулями **на сервере** (чтобы график не рвался).

### 3.3 Записи по статусам
```
appointments.aggregate([
  { $match: { businessId, startAt: { $gte: fromUtc, $lt: toUtc }, ...(staffId && { staffId }) } },
  { $group: { _id: "$status", count: { $sum: 1 } } }
])
```
Индекс: `{businessId, status, startAt}`.

### 3.4 Топ услуг — post-MVP (`DSH-04`) <!-- CHANGED: A2b -->
```
appointments.aggregate([
  { $match: { businessId, startAt: {…}, status: { $in: ["pending","confirmed","completed"] } } },
  { $group: { _id: "$serviceId", count: { $sum: 1 }, name: { $last: "$serviceSnapshot.name" } } },
  { $sort: { count: -1 } }, { $limit: n }
])
```
Для `sort=revenue`: отдельный `transactions.aggregate` по `appointmentId` → `$lookup` на `appointments` для `serviceId`, сумма со знаком; результат объединяется с названием из последней записи услуги. Название берётся из `serviceSnapshot.name` (устойчиво к переименованию/удалению услуги).

### 3.5 Загрузка мастера — MVP только как поле `CAL-01.load`; эндпоинт `DSH-03` — post-MVP <!-- CHANGED: A2b -->
Для каждого мастера (или одного при `staffId`) и каждой **локальной даты** периода:
1. `availableMinutes(day)` = длина рабочих отрезков (`computeWorkingIntervals`, BOOKING_ENGINE_SPEC §4) − пересечение с `blockedPeriods`;
2. `bookedMinutes(day)` = Σ `serviceSnapshot.durationMinutes` активных записей (`pending|confirmed|completed`) дня, обрезанных по границам дня;
3. сумма по периоду, `loadPercent = round(booked / available × 100)`, при `available = 0` → `null` («нет рабочих часов»), UI показывает «—».
Расчёт `availableMinutes` выполняется в сервисе (чистая функция + одна выборка расписаний/исключений/блокировок на период), `bookedMinutes` — агрегацией `appointments` по `staffId`. Buffer **не** входит в `bookedMinutes` (это не рабочая услуга). Формула общая для `DSH-03` и `CAL-01.load`.

### 3.6 Новые клиенты
`customers.countDocuments({ businessId, isDeleted:false, createdAt:{$gte,$lt} })`.

## 4. Виджеты (экран «Обзор»)

| Виджет | Данные | Вид |
|---|---|---|
| Фильтр периода | preset / даты (MVP); фильтр мастера — post-MVP | сегмент-контрол + date range |
| KPI-карточки (**4**, MVP) | выручка нетто · записи (всего) · отмены + no_show (число и доля) · новые клиенты; дельта к предыдущему периоду — post-MVP | стеклянные карточки (DESIGN_SYSTEM) <!-- CHANGED: A2b --> |
| График выручки (post-MVP) | `DSH-02` | линия/столбцы (Recharts) + таблица-альтернатива для скринридеров |
| Загрузка мастеров (post-MVP) | `DSH-03` | горизонтальные индикаторы с процентом и цветом мастера |
| Топ услуг (post-MVP) | `DSH-04` | таблица (название, кол-во, выручка) |
| Ближайшие записи | `DSH-05` | список с временем, клиентом, мастером, статусом; клик → запись |

Дельта: `(current − previous) / previous`, при `previous=0` → показывать «нет данных для сравнения».
Admin видит те же виджеты. Master — «Мой день» (`MST-01`): записи на сегодня, ближайшие 7 дней, число завершённых/no_show за месяц, **без денег**.

## 5. Пустые и ошибочные состояния

- Нет данных за период: KPI `0`/«—», график — пустое состояние «Нет оплат за выбранный период», кнопка «Создать запись»/«Принять оплату» (по правам).
- Новая организация (нет мастеров/услуг): чек-лист онбординга вместо виджетов (добавить мастера → услуги → расписание → публичная ссылка).
- Ошибка запроса отдельного виджета: локальное сообщение с «Повторить», остальные виджеты работают (каждый виджет — отдельный запрос).
- Загрузка: skeleton той же геометрии.

## 6. Производительность и кэш

Без отдельного кэша в MVP. Запросы покрыты индексами (§3). Ожидаемый порядок: десятки тысяч записей/бизнес — до сотен мс. Если `DSH-*` > 1 с на реальных объёмах — ввести предагрегаты (ADR при необходимости), не меняя API.
