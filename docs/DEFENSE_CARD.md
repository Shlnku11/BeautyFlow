# BeautyFlow — шпаргалка защиты

## Пять фраз

1. BeautyFlow — веб-CRM и онлайн-запись для салонов красоты.
2. Владелец управляет командой, расписанием, клиентами и оплатами из одного кабинета.
3. Клиент выбирает свободный слот на публичной странице и получает ссылку управления визитом.
4. Границы бизнеса и роли проверяются на сервере, а доступность слота пересчитывается при создании записи.
5. Демонстрация: лендинг → вход → календарь → публичная запись → оплата → карточка клиента.

## Пять технических фактов

- **125** unit/integration/API тестов в полном Vitest прогоне; исходный контрольный набор был **118**.
- **2/2** отдельные race-проверки.
- **23/23** Playwright E2E, включая OTP-регистрацию, demo owner/master и создание записи в календаре.
- `occupiedKeys` + уникальный индекс резервируют занятые интервалы мастера.
- `tenantPlugin` ограничивает доступ tenant, `withTransaction` атомарно сохраняет связанные изменения.

## Три вопроса

**Как исключён овербукинг?** Сервер заново проверяет график и занятость; `occupiedKeys` с уникальным индексом закрывают конфликт параллельных запросов, транзакция сохраняет связанные данные.

**Как разделены бизнесы?** У документов есть `businessId`; `tenantPlugin` ограничивает запрос активным бизнесом, а роли и permission-проверки ограничивают операции.

**Что осталось?** Production-развёртывание, backup restore, SMTP-доставка и реальный Google sign-in не проверены. OAuth credentials заданы локально, но origin/consent в Google Cloud требуют проверки. Для защиты показать локальный сайт и не обещать непроверенный production deploy.
